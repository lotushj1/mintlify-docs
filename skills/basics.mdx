## Skill 的基本概念

Skill 是一個**資料夾**，包含了教導 Claude 如何處理特定任務的指令。你可以把它想像成一份 SOP（標準作業流程），讓 Claude 每次都能用一致的方式完成工作。

<Note>
**官方定義**：Skill 是一組指令，打包成簡單的資料夾，教導 Claude 如何處理特定的任務或工作流程。
</Note>

---

## 核心設計原則

### 三層漸進式揭露

Skill 使用三層系統來優化效能：

| 層級 | 內容 | 何時載入 |
|-----|------|---------|
| **第一層** | YAML 設定區 | 總是載入，讓 Claude 知道何時該使用這個 Skill |
| **第二層** | SKILL.md 主體 | 當 Claude 認為這個 Skill 與當前任務相關時載入 |
| **第三層** | 連結的參考檔案 | 只有在需要時才載入 |

<Tip>
這種設計可以**最小化 Token 使用量**，同時保持專業能力。你不需要把所有內容都塞進一個檔案。
</Tip>

### 可組合性

Claude 可以同時載入多個 Skill。你的 Skill 應該能夠與其他 Skill 協同工作，而不是假設它是唯一的能力。

### 可移植性

Skill 在 Claude.ai、Claude Code 和 API 上的運作方式相同。建立一次，就能在所有平台使用。

## Skill 的完整檔案結構

一個完整的 Skill 資料夾可能包含：

```
your-skill-name/
├── SKILL.md          # 必要 - 主要的 Skill 檔案
├── scripts/          # 選用 - 可執行的程式碼
│   ├── process_data.py
│   └── validate.sh
├── references/       # 選用 - 參考文件
│   ├── api-guide.md
│   └── examples/
└── assets/           # 選用 - 範本、圖示等
    └── report-template.md
```

| 項目 | 說明 | 必要性 |
|-----|------|-------|
| `SKILL.md` | 主要的 Skill 檔案，包含設定和指令 | **必要** |
| `scripts/` | 可執行的腳本（Python、Bash 等） | 選用 |
| `references/` | 參考文件，需要時才載入 | 選用 |
| `assets/` | 範本、字型、圖示等資源 | 選用 |

<Warning>
**重要規則**：
- 主檔案必須命名為 `SKILL.md`（大小寫敏感）
- 不要在 Skill 資料夾中放 `README.md`
- 所有說明文件都應該放在 `SKILL.md` 或 `references/` 中
</Warning>

## YAML 設定區詳解

每個 Skill 都需要 YAML 設定區（frontmatter），這是 Claude 判斷是否載入 Skill 的關鍵。

### 基本格式

```yaml
---
name: your-skill-name
description: 這個 Skill 做什麼。當使用者說 [特定詞句] 時使用。
---
```

### 完整欄位說明

| 欄位 | 說明 | 必要性 |
|-----|------|-------|
| `name` | Skill 名稱，使用 kebab-case | **必要** |
| `description` | 說明 Skill 做什麼、何時使用 | **必要** |
| `license` | 開源授權（如 MIT、Apache-2.0） | 選用 |
| `compatibility` | 環境需求說明 | 選用 |
| `metadata` | 自訂欄位（作者、版本等） | 選用 |

### name 欄位規則

```yaml
# ✅ 正確
name: project-setup
name: daily-report
name: code-review

# ❌ 錯誤
name: Project Setup    # 不能有空格
name: project_setup    # 不能用底線
name: ProjectSetup     # 不能用大寫
```

### description 欄位技巧

description 是最重要的欄位，它決定了 Claude 何時會載入你的 Skill。

**必須包含**：
1. 這個 Skill **做什麼**
2. **何時**應該使用（觸發條件）

```yaml
# ✅ 好的 description
description: 分析 Figma 設計檔案並產生開發者交接文件。當使用者上傳 .fig 檔案、詢問「設計規格」、「元件文件」或「設計轉程式碼」時使用。

# ✅ 好的 description
description: 管理 Linear 專案工作流程，包含 Sprint 規劃、任務建立和狀態追蹤。當使用者提到「sprint」、「Linear 任務」、「專案規劃」或要求「建立 ticket」時使用。

# ❌ 不好的 description
description: 幫助處理專案。
# 問題：太模糊，沒有觸發條件

# ❌ 不好的 description
description: 建立複雜的多頁文件系統。
# 問題：沒有說明何時使用
```

### 完整 YAML 範例

```yaml
---
name: project-setup
description: 建立完整的專案工作區，包含資料夾結構、設定檔和初始文件。當使用者說「建立新專案」、「初始化專案」或「設定專案」時使用。
license: MIT
compatibility: 需要 Node.js 環境
metadata:
  author: Your Name
  version: 1.0.0
  tags: [project, setup, automation]
---
```

<Warning>
**安全限制**：
- 不能在設定區使用 XML 角括號（`<` 或 `>`）
- Skill 名稱不能包含「claude」或「anthropic」（保留字）
</Warning>

## Skill 的三種常見類型

根據官方指南，Skill 可以分為三種主要類型：

### 類型 1：文件與資產創建

用於建立一致、高品質的輸出，包括文件、簡報、程式碼等。

<Card title="範例：前端設計 Skill" icon="palette">
「建立獨特、可上線的前端介面，具有高設計品質。用於建立網頁元件、頁面、海報或應用程式。」
</Card>

**關鍵技巧**：
- 嵌入風格指南和品牌標準
- 使用範本結構確保一致性
- 最終確認前的品質檢查清單

### 類型 2：工作流程自動化

用於多步驟流程，受益於一致的方法論。

<Card title="範例：Skill Creator" icon="wand-magic-sparkles">
「建立新 Skill 的互動式指南。引導使用者定義用途、產生設定、撰寫指令並驗證。」
</Card>

**關鍵技巧**：
- 逐步工作流程，帶有驗證關卡
- 常見結構的範本
- 內建的審查和改進建議

### 類型 3：MCP 增強

為 MCP 伺服器提供的工具存取加上工作流程指導。

<Card title="範例：Sentry 程式碼審查 Skill" icon="bug">
「使用 Sentry 的錯誤監控資料，自動分析並修復 GitHub Pull Request 中偵測到的 Bug。」
</Card>

**關鍵技巧**：
- 協調多個 MCP 呼叫的順序
- 嵌入領域專業知識
- 提供使用者原本需要手動指定的上下文

## Skill 檔案放在哪裡？

簡單的 Skill（只有一個 `.md` 檔案）：

```
你的專案/
├── .claude/
│   └── skills/
│       ├── check-docs.md
│       └── daily-report.md
```

完整的 Skill（有額外資源）：

```
你的專案/
├── .claude/
│   └── skills/
│       └── project-setup/      # 資料夾形式
│           ├── SKILL.md
│           ├── scripts/
│           └── references/
```

<Note>
**重要**：Skill 檔案必須放在 `.claude/skills/` 資料夾中，Claude 才能找到它。
</Note>

## 命名規則

### 資料夾命名

| 格式 | 範例 | 結果 |
|-----|------|-----|
| ✅ kebab-case | `notion-project-setup` | 正確 |
| ❌ 有空格 | `Notion Project Setup` | 錯誤 |
| ❌ 底線 | `notion_project_setup` | 錯誤 |
| ❌ 大寫 | `NotionProjectSetup` | 錯誤 |

### 檔案與指令對應

| 檔案名稱 | 對應的指令 |
|---------|----------|
| `check-docs.md` | `/check-docs` |
| `daily-report.md` | `/daily-report` |
| `project-setup/SKILL.md` | `/project-setup` |

<Tip>
**命名建議**：
- 使用小寫英文字母
- 用連字號（-）分隔單字
- 名稱要簡短且容易記憶
- 名稱應該反映 Skill 的功能
</Tip>

## Skill 如何運作？

<Steps>
  <Step title="Claude 讀取設定區">
    當你開始對話時，Claude 會讀取所有 Skill 的 YAML 設定區（第一層），了解有哪些 Skill 可用。
  </Step>
  <Step title="判斷是否相關">
    當你提出請求時，Claude 根據 `description` 判斷哪個 Skill 與當前任務相關。
  </Step>
  <Step title="載入完整指令">
    如果判斷相關，Claude 載入該 Skill 的完整指令內容（第二層）。
  </Step>
  <Step title="按需載入參考">
    執行過程中，如果需要額外資訊，Claude 會載入 `references/` 中的檔案（第三層）。
  </Step>
  <Step title="執行並回傳結果">
    Claude 根據指令執行任務，完成後告訴你結果。
  </Step>
</Steps>

## 重要觀念

<AccordionGroup>
  <Accordion title="Skill 是以專案為單位的">
    你在 A 專案建立的 Skill，不會自動出現在 B 專案。如果想在多個專案使用相同的 Skill，需要複製到每個專案的 `.claude/skills/` 資料夾中。
  </Accordion>

  <Accordion title="Skill 可以帶參數">
    除了基本指令，你還可以在指令後面加上參數：
    ```
    /newsletter 本週 AI 新聞
    ```
    在 Skill 中可以用 `$ARGUMENTS` 取得參數內容。
  </Accordion>

  <Accordion title="Skill 使用自然語言">
    Skill 的指令內容使用自然語言撰寫，不需要學習程式語言。你只要用中文或英文描述你想要 Claude 做什麼就可以了。
  </Accordion>

  <Accordion title="多個 Skill 可以同時運作">
    Claude 可以同時載入多個 Skill。設計 Skill 時，應該考慮它能與其他 Skill 協同工作。
  </Accordion>

  <Accordion title="Skill 具有跨平台可移植性">
    同一個 Skill 可以在 Claude.ai、Claude Code 和 API 上使用，不需要修改。
  </Accordion>
</AccordionGroup>
