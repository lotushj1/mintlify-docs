## 快速診斷

遇到問題時，先確認以下幾點：

<Steps>
  <Step title="Skill 檔案位置正確嗎？">
    檔案必須放在 `.claude/skills/` 資料夾中
  </Step>
  <Step title="檔案格式正確嗎？">
    - 副檔名是 `.md`
    - 開頭有 `---` 包圍的設定區
    - `description` 有填寫內容
  </Step>
  <Step title="有重新啟動嗎？">
    某些工具需要重新啟動才會載入新的 Skill
  </Step>

## Skill 上傳錯誤

### 錯誤：Could not find SKILL.md in uploaded folder

<Accordion title="原因和解決方式">
**原因**：檔案沒有命名為 `SKILL.md`

**解決方式**：
- 將檔案重新命名為 `SKILL.md`（大小寫敏感）
- 使用 `ls -la` 確認檔案名稱正確
</Accordion>

### 錯誤：Invalid frontmatter

<Accordion title="原因和解決方式">
**原因**：YAML 格式錯誤

**常見錯誤**：
```yaml
# ❌ 錯誤 - 缺少分隔符號
name: my-skill
description: Does things

# ❌ 錯誤 - 引號沒有閉合
name: my-skill
description: "Does things

# ✅ 正確
---
name: my-skill
description: Does things
---
```
</Accordion>

### 錯誤：Invalid skill name

<Accordion title="原因和解決方式">
**原因**：名稱有空格或大寫字母

```yaml
# ❌ 錯誤
name: My Cool Skill

# ✅ 正確
name: my-cool-skill
```
</Accordion>

## Skill 無法使用

### 問題：輸入 `/skill名稱` 沒有反應

<AccordionGroup>
  <Accordion title="檢查 1：檔案位置是否正確">
    **正確的資料夾結構**：
    ```
    你的專案/
    ├── .claude/
    │   └── skills/
    │       └── your-skill.md  ← 檔案要放在這裡
    ```

    **常見錯誤**：
    - ❌ 放在 `claude/skills/`（少了前面的點）
    - ❌ 放在 `.claude/skill/`（少了 s）
    - ❌ 放在專案根目錄

    **解決方式**：
    把檔案移到正確的位置 `.claude/skills/` 資料夾中
  </Accordion>

  <Accordion title="檢查 2：檔案格式是否正確">
    **正確的格式**：
    ```markdown
    ---
    description: 這是 Skill 的說明
    ---

    這裡是 Skill 的內容...
    ```

    **常見錯誤**：
    - ❌ 沒有 `---` 包圍的設定區
    - ❌ `description` 拼錯字
    - ❌ 設定區的 `---` 不完整

    **解決方式**：
    確保檔案開頭有完整的設定區，包含 `description`
  </Accordion>

  <Accordion title="檢查 3：檔案副檔名是否正確">
    **正確的副檔名**：`.md`

    **常見錯誤**：
    - ❌ `.txt`
    - ❌ `.markdown`
    - ❌ 沒有副檔名

    **解決方式**：
    將檔案重新命名，確保副檔名是 `.md`
  </Accordion>

  <Accordion title="檢查 4：是否需要重新啟動">
    某些工具（如 Claude Desktop）需要重新啟動才會載入新的 Skill。

    **解決方式**：
    1. 完全關閉應用程式
    2. 重新開啟
    3. 再試一次 `/skill名稱`
  </Accordion>
</AccordionGroup>

### 問題：Skill 列表中看不到我的 Skill

<Accordion title="解決方式">
  1. 輸入 `/help` 或 `/` 查看可用的 Skill 列表
  2. 如果看不到，按照上面的檢查項目逐一確認
  3. 如果都正確但還是看不到，嘗試：
     - 重新啟動工具
     - 建立一個新的 Skill 測試（確認功能正常）
     - 檢查檔案是否有隱藏的特殊字元
</Accordion>

## Skill 觸發問題

### 問題：Skill 沒有在應該觸發時觸發（觸發不足）

<Accordion title="症狀和解決方式">
**症狀**：
- Skill 在應該載入時沒有載入
- 使用者需要手動啟用它
- 關於「何時使用」的問題很多

**解決方式**：在 description 中加入更多細節和觸發詞句

```yaml
# 修改前
description: 幫助處理專案。

# 修改後
description: 建立完整的專案工作區，包含資料夾結構、設定檔和初始文件。當使用者說「建立新專案」、「初始化專案」、「設定專案」或「project setup」時使用。
```

**除錯方式**：
詢問 Claude：「你什麼時候會使用 [skill name] Skill？」
Claude 會引用 description 回答，根據缺少的內容調整。
</Accordion>

### 問題：Skill 在不相關的查詢時觸發（觸發過度）

<Accordion title="症狀和解決方式">
**症狀**：
- Skill 為不相關的查詢載入
- 使用者停用它
- 對用途感到困惑

**解決方式**：

1. **加入否定觸發條件**
```yaml
description: 進階 CSV 檔案資料分析。用於統計建模、迴歸、聚類。不要用於簡單的資料探索（改用 data-viz Skill）。
```

2. **更具體地描述用途**
```yaml
# 太廣泛
description: 處理文件

# 更具體
description: 處理 PDF 法律文件，進行合約審查
```

3. **釐清範圍**
```yaml
description: PayFlow 電子商務支付處理。專門用於線上支付工作流程，不適用於一般財務查詢。
```
</Accordion>

## API 連線問題

### 問題：無法連接 OpenAI API（Whisper 等服務）

<AccordionGroup>
  <Accordion title="錯誤訊息：Invalid API Key">
    **可能原因**：
    - API Key 輸入錯誤
    - API Key 已過期或被撤銷
    - 複製時多了空格或少了字元

    **解決方式**：
    1. 前往 [OpenAI Platform](https://platform.openai.com/api-keys)
    2. 確認 API Key 是否有效
    3. 如果不確定，建立一個新的 API Key
    4. 重新設定，注意不要有多餘的空格
  </Accordion>

  <Accordion title="錯誤訊息：Insufficient quota / 額度不足">
    **可能原因**：
    - 帳號餘額不足
    - 沒有設定付費方式

    **解決方式**：
    1. 前往 [OpenAI Billing](https://platform.openai.com/account/billing)
    2. 確認已設定付費方式
    3. 查看帳號餘額，必要時加值
  </Accordion>

  <Accordion title="錯誤訊息：Rate limit exceeded / 超過使用限制">
    **可能原因**：
    - 短時間內發送太多請求
    - 帳號等級有使用限制

    **解決方式**：
    1. 等待幾分鐘後再試
    2. 如果經常發生，考慮升級帳號方案
    3. 在 Skill 中加入適當的間隔時間
  </Accordion>

  <Accordion title="錯誤訊息：Connection timeout / 連線逾時">
    **可能原因**：
    - 網路連線不穩定
    - 服務暫時不可用

    **解決方式**：
    1. 檢查網路連線
    2. 等待幾分鐘後再試
    3. 查看 [OpenAI Status](https://status.openai.com/) 確認服務狀態
  </Accordion>
</AccordionGroup>

### 問題：無法連接 Notion API

<AccordionGroup>
  <Accordion title="錯誤訊息：Unauthorized / 未授權">
    **可能原因**：
    - Integration Token 錯誤
    - 頁面沒有授權給 Integration

    **解決方式**：
    1. 確認 Token 正確（以 `secret_` 開頭）
    2. 開啟 Notion 頁面 → 點擊右上角 `...` → Connections
    3. 確認你的 Integration 有出現在列表中
    4. 如果沒有，點擊 **Connect to** 加入
  </Accordion>

  <Accordion title="錯誤訊息：Object not found / 找不到物件">
    **可能原因**：
    - Page ID 或 Database ID 錯誤
    - 頁面已被刪除或移動

    **解決方式**：
    1. 重新複製頁面網址，取得正確的 ID
    2. 確認頁面還存在
    3. 確認 Integration 有權限存取該頁面
  </Accordion>

  <Accordion title="錯誤訊息：Validation error / 驗證錯誤">
    **可能原因**：
    - 資料格式不符合 Database 欄位設定
    - 必填欄位沒有填寫

    **解決方式**：
    1. 檢查 Database 的欄位設定
    2. 確認 Skill 中的資料格式正確
    3. 確認所有必填欄位都有值
  </Accordion>
</AccordionGroup>

## 權限問題

### 問題：無法建立或寫入檔案

<AccordionGroup>
  <Accordion title="錯誤訊息：Permission denied / 權限被拒絕">
    **可能原因**：
    - 資料夾沒有寫入權限
    - 檔案被其他程式佔用

    **解決方式**：

    **Mac / Linux**：
    ```bash
    # 確認資料夾權限
    ls -la .claude/

    # 如果需要，修改權限
    chmod 755 .claude/
    chmod 755 .claude/skills/
    ```

    **Windows**：
    1. 右鍵點擊資料夾 → 內容 → 安全性
    2. 確認你的使用者有「寫入」權限
  </Accordion>

  <Accordion title="錯誤訊息：File is locked / 檔案被鎖定">
    **可能原因**：
    - 檔案正被其他程式開啟
    - 同步軟體（如 Dropbox）正在處理

    **解決方式**：
    1. 關閉可能正在使用該檔案的程式
    2. 等待同步軟體完成同步
    3. 重新嘗試操作
  </Accordion>
</AccordionGroup>

### 問題：MCP Server 無法存取外部服務

<Accordion title="解決方式">
  1. **確認 MCP Server 設定正確**
     - 檢查 `settings.json` 或相關設定檔
     - 確認 Token 和 API Key 正確

  2. **確認已重新啟動**
     - 修改 MCP 設定後必須重新啟動 Claude

  3. **確認服務有授權**
     - 例如 Notion 需要在頁面中授權 Integration
     - Google 服務需要完成 OAuth 授權流程
</Accordion>

## 輸出不如預期

### 問題：每次輸出的格式都不一樣

<Accordion title="解決方式">
  在 Skill 中加入更明確的格式要求：

  ```markdown
  ## 輸出格式（請嚴格遵守）

  請使用以下格式輸出，不要有任何變化：

  ### 標題
  [內容]

  ### 重點
  - 項目一
  - 項目二
  ```

  **小技巧**：
  - 提供具體的範例
  - 使用「請嚴格遵守」「必須」等強調詞
  - 說明「不要」做的事情
</Accordion>

### 問題：輸出內容不夠詳細

<Accordion title="解決方式">
  在 Skill 中加入詳細程度的要求：

  ```markdown
  ## 詳細程度要求

  - 每個段落至少 100 字
  - 每個重點要有說明和例子
  - 不要只列條目，要有完整的解釋
  ```
</Accordion>

### 問題：輸出包含不想要的內容

<Accordion title="解決方式">
  明確告訴 AI「不要」做什麼：

  ```markdown
  ## 注意事項

  請不要：
  - 不要加入 emoji
  - 不要使用英文
  - 不要加入額外的建議或評論
  - 不要在結尾加上「希望這對你有幫助」之類的話
  ```
</Accordion>

### 問題：指令沒有被遵循

<AccordionGroup>
  <Accordion title="原因 1：指令太冗長">
    **解決方式**：
    - 保持指令簡潔
    - 使用條列式和編號列表
    - 將詳細參考移到單獨的檔案
  </Accordion>

  <Accordion title="原因 2：重要指令被埋沒">
    **解決方式**：
    - 將關鍵指令放在最前面
    - 使用 `## 重要` 或 `## 關鍵` 標題
    - 必要時重複關鍵點

    ```markdown
    ## 重要：必須先執行

    在進行任何操作之前，必須先驗證輸入資料。
    ```
  </Accordion>

  <Accordion title="原因 3：語言模糊">
    ```markdown
    # ❌ 不好
    確保適當地驗證東西

    # ✅ 好
    關鍵：在呼叫 create_project 之前，驗證：
    - 專案名稱不為空
    - 至少指派一位團隊成員
    - 開始日期不在過去
    ```
  </Accordion>

  <Accordion title="原因 4：模型「懶惰」">
    有時候模型可能會跳過步驟。加入明確的鼓勵：

    ```markdown
    ## 效能注意事項

    - 花時間徹底完成這件事
    - 品質比速度更重要
    - 不要跳過驗證步驟
    ```

    <Tip>
    **提示**：將這些內容加到使用者提示比加在 SKILL.md 中更有效。
    </Tip>
  </Accordion>
</AccordionGroup>

## 大型上下文問題

### 問題：Skill 似乎變慢或回應品質下降

<Accordion title="原因和解決方式">
**可能原因**：
- Skill 內容太大
- 同時啟用太多 Skill
- 所有內容都被載入，而不是漸進式揭露

**解決方式**：

1. **優化 SKILL.md 大小**
   - 將詳細文件移到 `references/`
   - 使用連結而不是內嵌
   - 保持 SKILL.md 在 5,000 字以內

2. **減少啟用的 Skill 數量**
   - 評估是否同時啟用超過 20-50 個 Skill
   - 建議選擇性啟用
   - 考慮將相關功能整合成 Skill「套件」

3. **使用漸進式揭露**
   ```markdown
   ## 詳細說明

   關於 API 使用的完整說明，請參考 `references/api-guide.md`。
   ```
</Accordion>

## 還是無法解決？

<Steps>
  <Step title="收集錯誤資訊">
    把完整的錯誤訊息複製下來，包括：
    - 你輸入的指令
    - 完整的錯誤訊息
    - 使用的工具和版本
  </Step>
  <Step title="詢問 AI 助手">
    把錯誤資訊貼給 Claude，請它幫你分析：

    ```
    我在使用 Skill 時遇到這個錯誤：
    [貼上錯誤訊息]

    我的環境是：
    - 工具：[Claude Code / Cursor / 其他]
    - 作業系統：[Mac / Windows / Linux]

    請幫我分析可能的原因和解決方式。
    ```
  </Step>
  <Step title="搜尋社群資源">
    到以下地方尋找類似問題的解答：
    - [Claude Code GitHub Issues](https://github.com/anthropics/claude-code/issues)
    - [Anthropic Discord](https://discord.gg/anthropic)
  </Step>
  <Step title="回報問題">
    如果確定是 Bug，可以到 GitHub 回報：
    - 提供重現步驟
    - 附上錯誤訊息
    - 說明你的環境資訊
  </Step>
</Steps>

## 預防問題的好習慣

<Info>
**養成這些習慣，可以減少遇到問題的機會：**

1. **建立 Skill 後立即測試** - 不要等到要用的時候才發現問題
2. **保持檔案結構整潔** - 不要在 `.claude/skills/` 中放無關的檔案
3. **定期備份重要的 Skill** - 避免意外刪除或覆蓋
4. **API Key 妥善保管** - 不要分享或上傳到公開的地方
5. **注意服務額度** - 設定用量提醒，避免突然無法使用
</Info>
