## 設計模式

這些模式來自官方指南和早期採用者的經驗，代表了經過驗證的有效方法。

---

### 模式 1：順序工作流程編排

**適用情境**：使用者需要按照特定順序執行多步驟流程。

```markdown
## 工作流程：新客戶入職

### 步驟 1：建立帳號
呼叫工具：`create_customer`
參數：name, email, company

### 步驟 2：設定付款方式
呼叫工具：`setup_payment_method`
等待：付款方式驗證完成

### 步驟 3：建立訂閱
呼叫工具：`create_subscription`
參數：plan_id, customer_id（來自步驟 1）

### 步驟 4：發送歡迎信
呼叫工具：`send_email`
範本：welcome_email_template
```

**關鍵技巧**：
- 明確的步驟順序
- 步驟之間的依賴關係
- 每個階段的驗證
- 失敗時的回滾指令

---

### 模式 2：多服務協調

**適用情境**：工作流程跨越多個服務或 MCP。

```markdown
### 階段 1：設計匯出（Figma MCP）
1. 從 Figma 匯出設計資產
2. 產生設計規格
3. 建立資產清單

### 階段 2：資產儲存（Drive MCP）
1. 在 Drive 建立專案資料夾
2. 上傳所有資產
3. 產生分享連結

### 階段 3：任務建立（Linear MCP）
1. 建立開發任務
2. 將資產連結附加到任務
3. 指派給工程團隊

### 階段 4：通知（Slack MCP）
1. 在 #engineering 發布交接摘要
2. 包含資產連結和任務參考
```

**關鍵技巧**：
- 清楚的階段分離
- MCP 之間的資料傳遞
- 進入下一階段前的驗證
- 集中式錯誤處理

### 模式 3：迭代優化

**適用情境**：輸出品質可透過迭代改善。

```markdown
## 迭代報告建立

### 初稿
1. 透過 MCP 取得資料
2. 產生第一版報告
3. 儲存到暫存檔案

### 品質檢查
1. 執行驗證腳本：`scripts/check_report.py`
2. 識別問題：
   - 缺少的章節
   - 格式不一致
   - 資料驗證錯誤

### 優化循環
1. 處理每個識別的問題
2. 重新產生受影響的章節
3. 重新驗證
4. 重複直到達到品質門檻

### 最終確認
1. 套用最終格式
2. 產生摘要
3. 儲存最終版本
```

**關鍵技巧**：
- 明確的品質標準
- 迭代改進機制
- 驗證腳本
- 知道何時停止迭代

---

### 模式 4：上下文感知工具選擇

**適用情境**：相同結果，但根據上下文使用不同工具。

```markdown
## 智慧檔案儲存

### 決策樹
1. 檢查檔案類型和大小
2. 決定最佳儲存位置：
   - 大檔案（>10MB）：使用雲端儲存 MCP
   - 協作文件：使用 Notion/Docs MCP
   - 程式碼檔案：使用 GitHub MCP
   - 暫存檔案：使用本地儲存

### 執行儲存
根據決策：
- 呼叫適當的 MCP 工具
- 套用服務特定的 metadata
- 產生存取連結

### 向使用者說明
解釋為什麼選擇該儲存方式
```

**關鍵技巧**：
- 清楚的決策標準
- 備用選項
- 對選擇的透明度

### 模式 5：領域專業智慧

**適用情境**：你的 Skill 需要加入超越工具存取的專業知識。

```markdown
## 支付處理與合規檢查

### 處理前（合規檢查）
1. 透過 MCP 取得交易詳情
2. 套用合規規則：
   - 檢查制裁名單
   - 驗證司法管轄區許可
   - 評估風險等級
3. 記錄合規決策

### 處理
如果合規通過：
- 呼叫支付處理 MCP 工具
- 套用適當的詐欺檢查
- 處理交易
否則：
- 標記待審查
- 建立合規案例

### 稽核軌跡
- 記錄所有合規檢查
- 記錄處理決策
- 產生稽核報告
```

**關鍵技巧**：
- 領域專業知識嵌入邏輯
- 行動前的合規檢查
- 完整的文件記錄
- 清楚的治理

## 撰寫有效指令的最佳實踐

### 具體且可執行

```markdown
# ✅ 好的寫法
執行 `python scripts/validate.py --input {filename}` 檢查資料格式。
如果驗證失敗，常見問題包括：
- 缺少必填欄位（將它們加入 CSV）
- 無效的日期格式（使用 YYYY-MM-DD）

# ❌ 不好的寫法
在繼續之前驗證資料。
```

### 說明預期的輸出格式

```markdown
請使用以下格式輸出：

### 標題
[內容]

### 重點
- 項目一
- 項目二
```

### 考慮失敗情況

```markdown
如果沒有發現問題，請回覆「檢查完成，沒有問題」。
如果找不到相關資料，請告訴使用者「沒有找到相關內容」。
```

### 分步驟描述任務

```markdown
請依序執行：
1. 首先，檢查輸入檔案是否存在
2. 然後，驗證資料格式
3. 接著，處理資料
4. 最後，產生報告
```

### 清楚引用參考資源

```markdown
在撰寫查詢之前，請參考 `references/api-patterns.md` 了解：
- 速率限制指導
- 分頁模式
- 錯誤碼和處理方式
```

### 使用漸進式揭露

保持 SKILL.md 專注於核心指令。將詳細文件移到 `references/` 並連結到它。

```markdown
## 詳細說明
關於 API 使用的完整說明，請參考 `references/api-guide.md`。
```

### 1. 觸發測試

確保你的 Skill 在正確的時機載入。

**測試案例**：

```markdown
應該觸發：
- "幫我設定新的 ProjectHub 工作區"
- "我需要在 ProjectHub 建立專案"
- "初始化一個 Q4 規劃的 ProjectHub 專案"

不應該觸發：
- "舊金山的天氣如何？"
- "幫我寫 Python 程式碼"
- "建立一個試算表"
```

**除錯方式**：
詢問 Claude：「你什麼時候會使用 [skill name] Skill？」Claude 會引用 description 回答。根據缺少的內容調整。

### 2. 功能測試

驗證 Skill 產生正確的輸出。

```markdown
測試：建立包含 5 個任務的專案
前提：專案名稱「Q4 規劃」，5 個任務描述
當：Skill 執行工作流程
則：
- 專案在 ProjectHub 中建立
- 5 個任務以正確屬性建立
- 所有任務連結到專案
- 沒有 API 錯誤
```

### 3. 效能比較

證明 Skill 改善了結果。

```markdown
基準比較：

沒有 Skill：
- 使用者每次都要提供指令
- 15 次來回對話
- 3 次 API 呼叫失敗需要重試
- 消耗 12,000 tokens

有 Skill：
- 自動執行工作流程
- 只有 2 個釐清問題
- 0 次 API 呼叫失敗
- 消耗 6,000 tokens
```

## 定義成功標準

在建立 Skill 之前，先定義如何知道它是否有效。

### 量化指標

| 指標 | 目標 | 如何測量 |
|-----|-----|---------|
| 觸發準確率 | 90% 相關查詢觸發 | 執行 10-20 個測試查詢，追蹤自動載入次數 |
| 工具呼叫次數 | 在 X 次呼叫內完成 | 比較有/沒有 Skill 的相同任務 |
| API 失敗率 | 每個工作流程 0 次失敗 | 監控測試期間的 MCP 伺服器日誌 |

### 質化指標

| 指標 | 如何評估 |
|-----|---------|
| 使用者不需要提示下一步 | 測試時記錄需要重新導向或釐清的頻率 |
| 工作流程無需使用者修正即可完成 | 執行相同請求 3-5 次，比較結構一致性和品質 |
| 跨會話結果一致 | 新使用者能否在首次嘗試時用最少指導完成任務 |

## 迭代改進

Skill 是活的文件。根據以下情況計劃迭代：

### 觸發不足的信號

- Skill 在應該載入時沒有載入
- 使用者手動啟用它
- 關於何時使用的支援問題

**解決方案**：在 description 中加入更多細節和技術術語關鍵字

### 觸發過度的信號

- Skill 為不相關的查詢載入
- 使用者停用它
- 對用途的困惑

**解決方案**：加入否定觸發條件，更具體

```yaml
description: 進階 CSV 檔案資料分析。用於統計建模、迴歸、聚類。不要用於簡單的資料探索（改用 data-viz Skill）。
```

### 執行問題

- 結果不一致
- API 呼叫失敗
- 需要使用者修正

**解決方案**：改善指令，加入錯誤處理

## 處理模型「懶惰」

有時 Claude 可能會跳過步驟或給出較簡短的回應。加入明確的鼓勵：

```markdown
## 效能注意事項

- 花時間徹底完成這件事
- 品質比速度更重要
- 不要跳過驗證步驟
```

<Tip>
**注意**：將這些內容加到使用者提示比加在 SKILL.md 中更有效。
</Tip>

## 進階技巧：使用腳本進行驗證

對於關鍵驗證，考慮打包一個程式化執行檢查的腳本，而不是依賴語言指令。程式碼是確定性的；語言解釋不是。

```markdown
## 資料驗證

執行驗證腳本：
```bash
python scripts/validate.py --input data.csv
```

腳本會檢查：
- 必填欄位是否存在
- 日期格式是否正確
- 數值是否在有效範圍內

如果驗證通過，繼續處理。
如果驗證失敗，顯示錯誤訊息並停止。
```
