## 什麼是 Skill？

**Skill** 是 Claude Code 中的「快捷指令」功能。你可以把它想像成一個預先設定好的工作流程——只要輸入簡單的指令，Claude 就會自動執行一系列複雜的任務。

<Info>
**簡單來說**：Skill 就像是你手機上的捷徑功能，一鍵就能完成多個步驟。
</Info>

### 為什麼要使用 Skill？

| 沒有使用 Skill | 使用 Skill 後 |
|--------------|-------------|
| 每次都要重複輸入相同的指令 | 一個指令完成所有步驟 |
| 容易忘記某些步驟 | 確保每次都執行完整流程 |
| 需要記住複雜的操作順序 | 簡化為易記的短指令 |

---

## 如何使用 Skill

### 基本語法

在 Claude Code 中使用 Skill 非常簡單，只要輸入：

```
/skill名稱
```

例如：
- `/commit` - 自動整理並提交程式碼變更
- `/review-pr` - 檢查拉取請求（Pull Request）

### 使用範例

<Steps>
  <Step title="開啟 Claude Code">
    在終端機中輸入 `claude` 啟動 Claude Code
  </Step>
  <Step title="輸入 Skill 指令">
    直接輸入你想使用的 Skill，例如 `/commit`
  </Step>
  <Step title="等待執行">
    Claude 會自動執行 Skill 中定義的所有步驟
  </Step>
</Steps>

## 建立你的第一個 Skill

想要建立自己的 Skill？以下是簡單的步驟：

### 步驟 1：建立設定資料夾

首先，在你的專案根目錄建立 `.claude` 資料夾：

```
你的專案/
├── .claude/
│   └── skills/
│       └── my-skill.md
├── 其他檔案...
```

### 步驟 2：撰寫 Skill 檔案

在 `.claude/skills/` 資料夾中建立一個 Markdown 檔案。例如，建立一個名為 `check-docs.md` 的檔案：

```markdown
---
description: 檢查文件格式是否正確
---

請幫我檢查所有 MDX 文件，確認：
1. 每個檔案都有正確的 frontmatter（title 和 description）
2. 所有連結都是有效的
3. 程式碼區塊都有標註語言

如果發現問題，請列出需要修正的項目。
```

### 步驟 3：使用你的 Skill

建立完成後，你就可以使用這個 Skill：

```
/check-docs
```

<Tip>
**小提示**：Skill 的檔案名稱就是你使用時的指令名稱。`check-docs.md` 對應的指令就是 `/check-docs`。
</Tip>

## Skill 檔案結構說明

一個 Skill 檔案主要包含兩個部分：

```markdown
---
description: 這裡寫簡短的說明（會顯示在 /help 中）
---

這裡寫詳細的指令內容...
```

### 1. Frontmatter（設定區）

用 `---` 包圍的部分是設定區，目前支援：

| 欄位 | 說明 | 必填 |
|-----|------|-----|
| `description` | Skill 的簡短說明 | 建議填寫 |

### 2. 指令內容

設定區下方是實際要 Claude 執行的指令內容，你可以：
- 使用自然語言描述任務
- 列出步驟清單
- 包含特定的檢查項目

## 實用範例

### 範例 1：文件檢查 Skill

```markdown
---
description: 檢查文件是否符合團隊規範
---

請幫我檢查這個專案的文件：

## 檢查項目
1. 所有 MDX 檔案都有 title 和 description
2. 程式碼範例可以正確執行
3. 內部連結使用相對路徑
4. 圖片都有 alt 文字

## 輸出格式
- 如果全部通過，告訴我「檢查完成，沒有問題」
- 如果有問題，列出需要修正的檔案和具體問題
```

### 範例 2：每日總結 Skill

```markdown
---
description: 生成今日工作總結
---

請幫我整理今天的工作內容：

1. 查看今天的 Git 提交記錄
2. 整理主要的變更項目
3. 用簡潔的條列方式呈現

格式範例：
- [新增] 加入用戶登入功能
- [修正] 修復表單驗證問題
- [更新] 更新相依套件版本
```

### 範例 3：程式碼審查 Skill

```markdown
---
description: 快速審查程式碼品質
---

請幫我審查最近修改的程式碼：

## 審查重點
1. 是否有潛在的安全問題
2. 程式碼是否容易理解
3. 是否有重複的程式碼可以整合
4. 命名是否清楚明確

請用以下格式回報：
- 好的地方
- 建議改進的地方
- 需要立即修正的問題（如果有的話）
```

## 常見問題

<AccordionGroup>
  <Accordion title="Skill 沒有反應怎麼辦？">
    請確認：
    1. Skill 檔案放在正確的位置（`.claude/skills/` 資料夾）
    2. 檔案副檔名是 `.md`
    3. 指令名稱與檔案名稱一致（不含副檔名）
  </Accordion>

  <Accordion title="可以在 Skill 中使用變數嗎？">
    可以！你可以在 Skill 指令後加上參數。例如：
    ```
    /review-pr 123
    ```
    其中 `123` 就是傳遞給 Skill 的參數。
  </Accordion>

  <Accordion title="Skill 可以跨專案共用嗎？">
    目前 Skill 是依專案設定的。如果你想在多個專案中使用相同的 Skill，需要複製到每個專案的 `.claude/skills/` 資料夾中。
  </Accordion>

  <Accordion title="我可以修改內建的 Skill 嗎？">
    內建的 Skill（如 `/commit`）無法直接修改，但你可以建立一個新的 Skill 來覆蓋或擴展其功能。
  </Accordion>
</AccordionGroup>
